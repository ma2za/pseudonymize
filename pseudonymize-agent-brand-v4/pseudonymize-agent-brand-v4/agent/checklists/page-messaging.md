# Page & messaging QA

Run this after implementing or changing any route.

- [ ] The page has one explicit job.
- [ ] The H1 describes that job, not generic privacy/security ambition.
- [ ] The lead adds mechanism or context instead of restating the H1.
- [ ] Primary CTA names the next action precisely.
- [ ] The homepage demonstrates original → pseudonym while preserving context.
- [ ] Product page explains supported inputs and transformation behavior.
- [ ] Developer page uses real endpoints/payloads/packages only.
- [ ] Security page contains sourced claims only.
- [ ] Pricing page states the actual billing unit/model before decorative plan comparison.
- [ ] Docs copy is task-oriented, not marketing copy.
- [ ] App copy tells the user current state and next action.
- [ ] `Secure`, `anonymous`, `safe`, `compliant`, `zero retention`, `EU-only`, `encrypted`, `deterministic`, `reversible`, and similar claims are used only when verified.
- [ ] No fake testimonials, customers, metrics, badges, awards, SDKs, integrations, or plan features were created.
- [ ] Unsupported sections are omitted rather than filled with vague prose.
- [ ] Original sensitive values are not unnecessarily echoed in history/list UI.
- [ ] Errors say what failed and what the user can do next.
