# Trust / security copy framework

The brand should sound specific, technical and calm. Never imply security properties that have not been verified.

## Required proof points before launch
1. Processing location / region.
2. Data retention behavior and exact retention windows.
3. Encryption in transit and at rest.
4. Tenant isolation model.
5. Subprocessors.
6. Logging and whether logs can contain source data.
7. Mapping / re-identification storage model.
8. Deletion workflow and backups.
9. Authentication / SSO / MFA support.
10. DPA / GDPR roles.
11. Certifications or audits, only if actually completed.

## Good pattern
**Data retention**
Source files are deleted <verified time> after processing. <Any exact exception>.

## Bad pattern
Your data is always completely safe.

## Homepage trust section
Use four factual cards: Processing / Retention / Cryptography / Assurance. If a fact is not yet strong enough to publish, leave it off rather than replacing it with a shield icon.
