# pseudonymize.io — Production visual identity

## Brand idea
**Keep the structure. Lose the identity.**

The product is a privacy transformation layer. The identity is built around a visible before → after operation: original identifiers are detached and replaced by consistent machine-readable pseudonyms while the surrounding structure stays intact. Security is expressed through precision and inspectability, not fear imagery.

## Personality
Precise · calm · technical · trustworthy · restrained · infrastructure-grade.

## Visual territory
- Dark Ink base, off-white text, rare Cipher Green accent.
- Mono typography exclusively for machine-readable values, pseudonyms, API examples and technical metadata.
- Thin rails and before→after relationships are the signature graphic device.
- Borders before shadows; negative space before decoration.
- Diagrams before illustrations; real UI before abstract art.

## Logo
The lowercase `p` is divided by a Cipher Green transformation cut. It encodes pseudonym / person / record plus a visible separation boundary. Use the lockup in most first-contact contexts so the cut cannot be mistaken for a generic prohibition symbol.

## Color
Ink `#081016` · Text `#EEF5F7` · Surface `#121F29` · Line `#263843` · Cipher `#48D6B0` · Muted `#758690`.

Cipher Green means transformed/protected output. It is not decorative confetti and should occupy roughly 5% of most interfaces.

## Typography
Primary: **Inter**. Technical: **IBM Plex Mono**. The package does not redistribute font files. Use package/webfont sources in the implementation.

## Core product grammar
Original → detection → pseudonymized output.

`Alice Morgan → PERSON_7F2A`
`alice@example.com → EMAIL_1C9D`
`Munich → CITY_03E4`

This grammar should appear consistently across website, app, docs, social cards and presentations.

## Layout
Marketing max-width 1180 px. Reading width 720 px. 12-column conceptual grid. Main radii 8–14 px. Avoid giant rounded startup blobs.

## Security visual language
Do not use locks/shields unless the content literally discusses a security control. Trust sections are factual proof cards: processing, retention, cryptography, assurance. No fake badges.

## Product UI
The application is dense but calm. Editor/output pairs use split panes. Original values can receive a restrained rose highlight during review; pseudonymized values use Cipher Green. After processing, hiding original PII by default is preferred where workflow permits.

## Docs
Light mode by default for reading. API examples remain on dark code surfaces. Product and docs use exactly the same token colors and entity vocabulary.

## Email
Light, plain, transactional. Security-sensitive emails explain event, time, scope and action. No decorative illustrations.

## Motion
Transformation motion only: highlight 120 ms → replace 180–220 ms → settle 140 ms. Respect reduced motion. Avoid background motion that does not explain state.

## Accessibility
Target WCAG 2.2 AA. Color never carries meaning alone. Visible focus states. Mobile before/after layouts stack into linear reading order.
