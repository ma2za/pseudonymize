One privacy layer

Different data in. One consistent transformation.

The visual system treats pseudonymization as a controlled conversion, not a mysterious security ritual. The product should make every step inspectable.

01 / TEXT

Free-form text

Detect names, emails, phone numbers, locations and other configured entities while preserving sentence structure and meaning.

Alice → PERSON_7F2A
02 / TABLES

Structured data

Pseudonymize columns consistently across CSVs, exports and datasets without breaking relationships between records.

customer_id → CUST_91C4
03 / FILES

Working files

Run documents through the same policy layer and review detected entities before using the output downstream.

report.pdf → safe/report.pdf
The signature interaction

Privacy that leaves the useful parts alone.

Pseudonymization is not redaction. The interface should make that distinction obvious within seconds.

Original

Sensitive identifiers are visible and attached to the underlying information.

Please contact Alice Morgan

Developer first

Put privacy before the next system.

Use pseudonymize.io as a transformation boundary between sensitive source data and analytics, AI, support, development or third-party tooling.

01
Stable pseudonyms. Preserve record-level relationships where your configuration requires them.
02
Reviewable output. Make detected entities and replacements visible instead of hiding the process.
03
Policy-driven. Different workflows can pseudonymize different entity types.
curl https://api.pseudonymize.io/v1/text \
  -H "Authorization: Bearer $PZ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Alice lives in Munich",
    "policy": "default"
  }'

  "entities": 2
