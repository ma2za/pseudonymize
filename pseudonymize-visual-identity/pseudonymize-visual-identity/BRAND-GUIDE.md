# pseudonymize.io — Visual Identity System

## 1. Brand idea

**Keep the structure. Lose the identity.**

pseudonymize.io is privacy infrastructure for data that still needs to remain useful.  
The visual system should therefore communicate four things at once:

1. **Separation** — identity is detached from the underlying data.
2. **Continuity** — the structure and usefulness of the content remain intact.
3. **Control** — the transformation is deliberate, deterministic, inspectable.
4. **Calm security** — serious privacy without fear-based cyber-security clichés.

The brand should feel closer to excellent developer infrastructure than to a compliance consultancy.

### Brand attributes
Precise · calm · technical · trustworthy · restrained · modern · deterministic · infrastructure-grade

### Avoid
Shields, padlocks, fingerprint stock art, neon hacker aesthetics, Matrix rain, excessive gradients, “military-grade” language, generic AI sparkles, glossy 3D blobs.

---

## 2. Logo system

### Primary symbol: the divided `p`

The mark is a lowercase `p` crossed by a diagonal cipher line.

The `p` represents:
- pseudonym
- person / personally identifiable information
- a structured record

The diagonal line represents:
- identity separation
- transformation
- token substitution
- a clean boundary between original and pseudonymized data

The symbol should remain extremely simple and legible at favicon size.

### Wordmark
Use lowercase **pseudonymize** with `.io` rendered in mono and the accent color.

Preferred lockup:
`[mark] pseudonymize.io`

Do not uppercase the brand except in legal or highly constrained contexts.

### Clear space
Maintain at least half the mark width on all sides.

### Minimum sizes
- Mark: 16 px digital
- Horizontal lockup: 120 px wide
- Wordmark: 96 px wide

## 3. Color system

### Core
- Ink — `#0A0F14`
- Ink 2 — `#111820`
- Surface — `#151E27`
- Surface 2 — `#1B2631`
- Line — `#263441`
- Text — `#EAF1F5`
- Muted — `#8A9AAA`

### Light mode
- Paper — `#F6F8FA`
- Paper 2 — `#EEF2F5`
- Paper line — `#D7E0E7`
- Paper text — `#111820`

### Signature accent
- Cipher — `#35D0A5`
- Cipher hover — `#29BA91`
- Cipher soft — `#CFF7EB`

Cipher green is not “success green.” It specifically means **protected, transformed, or safely processed**.

### Semantic
- Info — `#69A7FF`
- Warning — `#E7B04A`
- Danger — `#E86A6A`

Use semantic colors only for actual state. Do not decorate random UI with them.

### Recommended ratio
80% neutral / 15% secondary neutral / 5% Cipher accent.

## 4. Typography

### Primary
**Manrope**
- Display: 650–700
- Headings: 600–650
- Body: 400–500
- UI labels: 500–600

Reason: geometric and technical without feeling cold or sci-fi.

### Technical / data
**IBM Plex Mono**
Use for:
- pseudonyms
- transformed values
- file metadata
- API examples
- inline tokens
- `.io` in the wordmark
- status labels when appropriate

Do not use mono for long body copy.

### Type scale
- Hero: 64 / 68
- H1: 48 / 54
- H2: 36 / 42
- H3: 26 / 32
- Body large: 18 / 29
- Body: 16 / 26
- Small: 14 / 22
- Label: 12 / 16, optional uppercase + 0.06em tracking

## 5. Core graphic language

The signature graphic is a **before → pseudonymized** transformation.

Example:

`Alice Morgan        → PERSON_7F2A`  
`alice@example.com   → EMAIL_1C9D`  
`+49 151 555 0192    → PHONE_88B1`  
`Munich              → CITY_03E4`

This can appear in:
- hero sections
- empty states
- product screenshots
- documentation
- social graphics
- loading animations
- conference booths
- onboarding

The transformation is the brand. Use it more than decorative illustration.

### Token pills
Pseudonymized values can appear inside subtle outlined pills:
`PERSON_7F2A`
`EMAIL_1C9D`

No rounded rainbow chips. Keep them quiet and systematic.

### Data rails
Thin horizontal lines connecting original values to pseudonyms can become a recurring motif.

## 6. Layout

### Principles
- Wide negative space
- Strong 12-column grid on marketing pages
- Narrow reading widths for prose
- Technical content aligned on a stricter baseline
- Borders before shadows
- Dark surfaces used as purposeful “processing zones”

### Radius
- Small: 6 px
- Medium: 10 px
- Large: 14 px

Avoid giant 24–32 px startup-card radii unless on a single hero container.

### Borders
1 px, low contrast.  
Borders should define structure, not shout.

### Shadows
Use almost none.
- small: utility menus
- medium: floating dialog or elevated product preview

## 7. UI direction

### Primary button
Cipher background, Ink text.
Text examples:
- Pseudonymize file
- Try pseudonymize.io
- Create workspace

### Secondary button
Transparent with neutral border.

### Tertiary
Text-only.

### Inputs
- flat surface
- 1 px border
- 8–10 px radius
- visible focus ring in Cipher
- mono where the content is inherently technical

### Cards
Use for meaningful objects only:
- file
- dataset
- job
- policy
- transformation result

Not every paragraph deserves a card. Humanity has suffered enough nested rectangles.

## 11. Motion

Motion should communicate transformation.

### Signature interaction
Original value morphs into pseudonym:
`Alice Morgan` → `PERSON_7F2A`

Suggested timing:
- highlight entity: 120 ms
- transform: 180–220 ms
- settle: 140 ms

### Hover
Subtle 1–2 px movement maximum.

### Loading
Use a scanning line that moves through rows and replaces sensitive fields with stable pseudonyms.

Avoid spinning shield animations. Nobody has ever felt safer because a shield rotated.

## 12. Tone of voice

### Style
Short, concrete, calm.

### Preferred
- Pseudonymize sensitive data before it leaves your workflow.
- Detect sensitive entities and replace them with consistent pseudonyms.
- Keep datasets useful without keeping real identities attached.
- Process text, tables and files through one privacy layer.

### Avoid
- Revolutionary privacy
- Military-grade
- Unhackable
- Bulletproof
- Zero-risk
- AI-powered privacy magic
- Compliance guaranteed

Security claims should be specific and verifiable.

## 14. Homepage visual direction

### Hero
Left:
- headline
- 2-line explainer
- primary CTA
- docs CTA

Right:
live transformation panel showing raw data becoming pseudonymized.

### Trust strip
Use actual, verifiable statements:
- deployment model
- encryption
- supported file formats
- subprocessors
- certifications
- data retention

Never invent trust badges.

### Product section
Show three inputs:
1. text
2. tables / CSV
3. files

Then show a shared transformation layer.

### How it works
1. detect
2. transform
3. use safely

### Developer section
Dark code panel with API example.

### Final CTA
No giant illustration. Just copy + CTA + one transformation row.

## 18. Product screenshots

Product screenshots should:
- use real UI
- contain synthetic example data only
- show one obvious transformation
- crop tightly
- avoid browser chrome unless context matters
- use a 1 px neutral border
- use 12–14 px corner radius
- use very subtle shadow

---

## 19. CSS principles

- Accent color is rare.
- Prefer neutral surfaces.
- Use mono for machine-readable values.
- Maintain high contrast.
- Focus rings are always visible.
- Dark mode is the signature marketing mode.
- Product may support both light and dark.
- Avoid gratuitous gradients.
